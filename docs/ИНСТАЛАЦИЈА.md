# Упатство за инсталација и конфигурација

**е-Кабинет · Општина Битола** — нова инсталација од почеток, без пренос на податоци од друг систем или од друга општина.

Ова упатство е наменето за администраторот на системот (IT одделение на Општина Битола или изведувачот). Чекорите
се напишани за **Ubuntu Server 22.04 / 24.04 LTS** со Apache и PHP-FPM, и **Microsoft SQL Server 2019/2022**
(на Windows или Linux). Во примерите се користат следните вредности — заменете ги со вистинските:

| Вредност во примерите | Значење |
| --- | --- |
| `ekabinet.bitola.example` | домен на апликацијата (на пр. `ekabinet.bitola.gov.mk`) |
| `sql.bitola.example` | SQL Server на Општината |
| `ekabineti_bitola` | име на базата на податоци |
| `ekabineti_bitola_app` | SQL најава на апликацијата (само читање/запишување) |
| `/var/www/ekabineti-bitola` | основна папка на инсталацијата |

## 1. Што се инсталира

- Веб-апликација на PHP (без framework): `php81/public` е единствената јавна папка.
- База на податоци на Microsoft SQL Server. Сите текстови се чуваат во Unicode колони (`NVARCHAR`), а базата се
  создава со колацијата **`Macedonian_FYROM_100_CI_AS`** — правилно подредување (А, Б, В, Г, Д, Ѓ, Е …),
  пребарување без разлика на големи/мали букви и споредби на македонска кирилица.
- Приватни датотеки (документи, фотографии, увози, логови) во `php81/storage` — никогаш не се достапни директно преку веб.
- Почетни податоци: системски улоги и дозволи, почетна организациска поставеност на Општина Битола (сектори, кои
  можат да се менуваат), пример буџетска програма. **Нема проекти, корисници (освен првиот администратор),
  буџети или предмети од друга инсталација.**

## 2. Предуслови

| Компонента | Верзија / забелешка |
| --- | --- |
| Оперативен систем | Ubuntu Server 22.04 или 24.04 LTS (64-bit), мин. 2 vCPU, 4 GB RAM, 40 GB диск |
| PHP | 8.1, 8.2 или 8.3 со PHP-FPM |
| PHP проширувања | `pdo_sqlsrv`, `sqlsrv`, `curl`, `fileinfo`, `mbstring`, `openssl`, `sodium`, `zip`, `simplexml`, `xml`, `intl` (препорачано), `gd` (препорачано) |
| Драјвер | Microsoft ODBC Driver 18 for SQL Server |
| SQL Server | 2019 или 2022 (Standard/Express/Enterprise), TCP 1433, TLS сертификат |
| Веб-сервер | Apache 2.4 (`mod_rewrite`, `mod_headers`, `mod_proxy_fcgi`) или Nginx |
| Алатки | LibreOffice (headless) за `.xls`/`.doc`, `poppler-utils` (`pdftotext`) за PDF во AI прикачувањето |
| Опционално | ClamAV, Microsoft 365 (Graph) за е-пошта, OpenAI API клуч, Google Cloud сервисна сметка |
| Мрежа | Излезен HTTPS од серверот до: `login.microsoftonline.com`, `graph.microsoft.com`, `api.openai.com`, `oauth2.googleapis.com`, `sheets.googleapis.com` (само за користените интеграции), `tile.openstreetmap.org` (мапи во прелистувачот) |

## 3. Подготовка на серверот

### 3.1 PHP и основни пакети

Ubuntu 22.04 (PHP 8.1):

```bash
sudo apt update
sudo apt install -y apache2 php8.1-fpm php8.1-cli php8.1-dev php8.1-mbstring php8.1-xml php8.1-zip php8.1-curl php8.1-intl php8.1-gd php-pear unixodbc-dev
```

Ubuntu 24.04 (PHP 8.3) — истите пакети со префикс `php8.3-`. Во продолжение заменете `8.1` со вашата верзија.

### 3.2 Microsoft ODBC Driver 18 и `pdo_sqlsrv`

```bash
curl -fsSL https://packages.microsoft.com/keys/microsoft.asc | sudo gpg --dearmor -o /usr/share/keyrings/microsoft-prod.gpg
curl -fsSL https://packages.microsoft.com/config/ubuntu/$(lsb_release -rs)/prod.list | sudo tee /etc/apt/sources.list.d/mssql-release.list
sudo apt update
sudo ACCEPT_EULA=Y apt install -y msodbcsql18 mssql-tools18
```

```bash
sudo pecl install sqlsrv pdo_sqlsrv
```

```bash
printf "; priority=20\nextension=sqlsrv.so\n" | sudo tee /etc/php/8.1/mods-available/sqlsrv.ini
printf "; priority=30\nextension=pdo_sqlsrv.so\n" | sudo tee /etc/php/8.1/mods-available/pdo_sqlsrv.ini
sudo phpenmod -v 8.1 sqlsrv pdo_sqlsrv
sudo systemctl restart php8.1-fpm
```

Проверка: `php -m | grep -i sqlsrv` треба да ги прикаже `pdo_sqlsrv` и `sqlsrv`.

### 3.3 Алатки за документи

```bash
sudo apt install -y --no-install-recommends libreoffice-calc libreoffice-writer poppler-utils
```

LibreOffice се користи за читање стари Excel (`.xls`) и Word (`.doc`) датотеки; `pdftotext` за PDF извештаи.

### 3.4 Регионални поставки

Апликацијата работи со временската зона **`Europe/Skopje`** (се поставува во конфигурацијата). Препорачливо е и
серверот да ја користи:

```bash
sudo timedatectl set-timezone Europe/Skopje
```

## 4. SQL Server и база со македонска кирилица

1. На SQL Server вклучете TCP/IP (порта 1433) и инсталирајте TLS сертификат издаден за името на серверот
   (на пр. `sql.bitola.example`). Во продукција не користете `trust_server_certificate = true`.
2. Отворете ја портата 1433 само кон веб-серверот на е-Кабинет (firewall).
3. Подгответе SQL најава со права `sysadmin` (или `dbcreator` + `securityadmin`) само за инсталацијата.
   Апликацијата потоа работи со посебна најава со ограничени права (`db_datareader`, `db_datawriter`).
4. Проверете дека колацијата постои:

   ```sql
   SELECT name FROM sys.fn_helpcollations() WHERE name = N'Macedonian_FYROM_100_CI_AS';
   ```

Базата ја создава инсталатерот (чекор 8) со `COLLATE Macedonian_FYROM_100_CI_AS`. Ако DBA тимот претпочита рачно
создавање, користете [`deploy/sql/create-production-database.sql`](../deploy/sql/create-production-database.sql):

```bash
sqlcmd -S sql.bitola.example -U sa -C -i deploy/sql/create-production-database.sql -v AppPassword="<силна лозинка>" DeployPassword="<силна лозинка>"
```

> Базата мора да биде **празна** (без табели) кога се извршува инсталатерот. Инсталатерот одбива да менува база
> во која веќе постојат табели — нема пренос ниту пребришување на постојни податоци.

## 5. Преземање на кодот и структура на папките

```bash
sudo mkdir -p /var/www/ekabineti-bitola/shared
sudo git clone https://github.com/brahaluftar/ekabineti.mk.git /var/www/ekabineti-bitola/repo
sudo ln -sfn /var/www/ekabineti-bitola/repo/php81 /var/www/ekabineti-bitola/current
```

Структура:

```
/var/www/ekabineti-bitola/
├── shared/e-kabineti.php      ← приватна конфигурација (чекор 6)
├── repo/                      ← Git клон на ekabineti.mk
│   └── php81/
│       ├── public/            ← DocumentRoot
│       └── storage/           ← приватни датотеки и логови (запишување за www-data)
└── current -> repo/php81
```

Дозволи:

```bash
sudo chown -R root:www-data /var/www/ekabineti-bitola/repo
sudo chown -R www-data:www-data /var/www/ekabineti-bitola/repo/php81/storage
sudo find /var/www/ekabineti-bitola/repo/php81/storage -type d -exec chmod 750 {} \;
```

Апликацијата ја бара конфигурацијата по следниот редослед: променливата `EKABINETI_CONFIG`,
`/var/www/ekabineti-bitola/shared/e-kabineti.php` (две нивоа над `php81`), `…/repo/shared/e-kabineti.php`,
`php81/config/e-kabineti.php`.

## 6. Приватна конфигурација

```bash
sudo cp /var/www/ekabineti-bitola/repo/php81/config/e-kabineti.php.example /var/www/ekabineti-bitola/shared/e-kabineti.php
sudo chown root:www-data /var/www/ekabineti-bitola/shared/e-kabineti.php
sudo chmod 640 /var/www/ekabineti-bitola/shared/e-kabineti.php
```

Уредете ја датотеката и внесете ги вредностите на Општина Битола:

| Клуч | Опис |
| --- | --- |
| `app.url` | `https://ekabinet.bitola.example` — мора да започнува со `https://` во продукција |
| `app.timezone` | `Europe/Skopje` |
| `app.session_name` | име на колачето за сесија, на пр. `ekabinet_bitola_session` |
| `app.health_token` | случајна вредност од најмалку 32 знаци: `php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"` |
| `app.trusted_proxies` | IP-адреси на reverse proxy / load balancer (ако постои) |
| `database.host`, `database.port` | `sql.bitola.example`, `1433` |
| `database.name` | `ekabineti_bitola` |
| `database.collation` | `Macedonian_FYROM_100_CI_AS` (користи го инсталатерот) |
| `database.username`, `database.password` | најава на апликацијата, на пр. `ekabineti_bitola_app` (инсталатерот ја создава ако не постои) |
| `database.encrypt` | `true` |
| `database.trust_server_certificate` | `false` во продукција |
| `database.hostname_in_certificate` | името во TLS сертификатот на SQL Server |
| `graph.*` | Microsoft Graph за е-пошта — чекор 11 (почетно `enabled => false`) |
| `google_sheets.*` | опционален панел — чекор 13 |
| `openai.*` | AI асистенти — чекор 12 |
| `uploads.clamav_binary` | патека до `clamdscan`/`clamscan` или `null` |

Тајните (лозинки, клучеви) може да се чуваат и како променливи на средината во PHP-FPM pool
(`/etc/php/8.1/fpm/pool.d/www.conf`, на пр. `env[OPENAI_API_KEY] = ...`), а не во датотеката.

Проверка на серверот и конфигурацијата:

```bash
sudo -u www-data php /var/www/ekabineti-bitola/current/bin/preflight.php
```

Сите проверки треба да бидат `[OK]`.

## 7. Веб-сервер и HTTPS

### Apache

```bash
sudo a2enmod rewrite headers proxy_fcgi setenvif ssl
sudo a2enconf php8.1-fpm
sudo cp /var/www/ekabineti-bitola/repo/deploy/apache/ekabineti-bitola.conf /etc/apache2/sites-available/
sudo sed -i 's/__DOMAIN__/ekabinet.bitola.example/' /etc/apache2/sites-available/ekabineti-bitola.conf
sudo a2ensite ekabineti-bitola
sudo a2dissite 000-default
sudo systemctl reload apache2
```

HTTPS сертификат (Let's Encrypt или сертификат на Општината):

```bash
sudo apt install -y certbot python3-certbot-apache
sudo certbot --apache -d ekabinet.bitola.example
```

### Nginx (алтернатива)

```nginx
server {
    listen 443 ssl http2;
    server_name ekabinet.bitola.example;
    root /var/www/ekabineti-bitola/current/public;
    index index.php;
    client_max_body_size 70m;
    # ssl_certificate / ssl_certificate_key ...
    location / { try_files $uri /index.php?$query_string; }
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.1-fpm.sock;
        fastcgi_param HTTP_AUTHORIZATION $http_authorization;
    }
    location ~ /\. { deny all; }
}
```

Ограничувањата за прикачување (`upload_max_filesize=64M`, `post_max_size=70M`) се поставени во
`php81/public/.user.ini`; за Nginx/PHP-FPM поставете ги и во `php.ini` ако `.user.ini` не се чита.

## 8. Создавање на базата, првиот администратор и миграциите

### 8.1 Инсталатер

```bash
cd /var/www/ekabineti-bitola/current
sudo -u www-data php bin/install-database.php
```

Инсталатерот:

1. бара потврда `CREATE ekabineti_bitola`;
2. бара корисничко име и лозинка на SQL администраторот (не се зачувуваат);
3. го бара првиот администратор на апликацијата: корисничко име, е-пошта, име и презиме, лозинка
   (најмалку 14 знаци, мала и голема буква, број и симбол);
4. ја создава базата со колација `Macedonian_FYROM_100_CI_AS` (ако не постои), ја создава најавата на апликацијата,
   ги извршува `schema.sql` и `seed-production.sql` во една трансакција и му ја доделува улогата
   **Администратор на системот** на првиот корисник.

Неинтерактивно (на пр. во скрипта), со променливи на средината:

```bash
EKABINETI_INSTALL_CONFIRM="CREATE ekabineti_bitola" EKABINETI_SQL_ADMIN_USER=sa EKABINETI_SQL_ADMIN_PASSWORD='...' EKABINETI_INITIAL_ADMIN_USERNAME=admin EKABINETI_INITIAL_ADMIN_EMAIL=admin@bitola.example EKABINETI_INITIAL_ADMIN_NAME="Администратор на системот" EKABINETI_INITIAL_ADMIN_PASSWORD='...' EKABINETI_INITIAL_ADMIN_PASSWORD_CONFIRM='...' php bin/install-database.php
```

### 8.2 Миграции

Миграциите ја дополнуваат шемата до тековната верзија (Правна служба, приходи, брифинзи, каталог на услуги,
работни области итн.). Се извршуваат со SQL сметка со права за промена на шемата (`db_owner`):

```bash
sudo -u www-data php bin/migrate.php
```

Командата е идемпотентна: секоја миграција се извршува еднаш и се евидентира во `dbo.migrations`.
Миграциите не внесуваат податоци од друга општина.

### 8.3 Проверка

```bash
curl -s -H "Authorization: Bearer <app.health_token>" https://ekabinet.bitola.example/health/details
```

Очекуван одговор: `"status":"ok"` (база, шема и складиште се исправни).

Проверка на колацијата:

```sql
SELECT DATABASEPROPERTYEX(N'ekabineti_bitola', 'Collation');   -- Macedonian_FYROM_100_CI_AS
```

## 9. Распоредувач (cron)

```bash
sudo cp /var/www/ekabineti-bitola/repo/deploy/cron/ekabineti-bitola /etc/cron.d/ekabineti-bitola
sudo chmod 644 /etc/cron.d/ekabineti-bitola
```

Распоредувачот (`bin/scheduler.php`, на секои 5 минути) ги испраќа потсетувањата и сумарните е-пораки, ги
генерира неделните брифинзи (понеделник), ги скенира прикачените документи и ги обработува увозите на приходи.
`bin/process-notifications.php` ги испраќа известувањата на чекање секоја минута.

## 10. Прва најава и почетно поставување

Најавете се на `https://ekabinet.bitola.example` со првиот администратор. Препорачан редослед:

1. **Администрација → Сектори** — проверете ја почетната поставеност и прилагодете ја на актуелниот правилник за
   систематизација (називи, шифри). Шифрите `FIN` (финансии), `PRAV` (Правна служба) и `INS` (инспекција) ги
   користи апликацијата за посебни права — не ги менувајте, само називите. Во „Буџетски шифри“ внесете ги шифрите
   на програмите од буџетот на Општината.
2. **Администрација → Улоги и дозволи** — по потреба создадете нови улоги врз основните (на пр. „Службеник за
   матична евиденција“).
3. **Администрација → Корисници** — создајте ги корисниците (Градоначалник, Кабинет, раководители на сектори,
   финансии, Правна служба …) и доделете им улога и сектор. Корисниците можат и сами да се регистрираат;
   сметката се активира кога администраторот ќе ѝ додели улога.
4. **Работни области** — проверете ги областите (инфраструктура, образование, здравство …) и секторите во нив.
5. **Услуги за граѓани → Каталог** — внесете ги услугите на Општината по сектори и одделенија, шалтерите за
   известување и службениците што известуваат.
6. **Буџет и финансии → Увоз** — увезете го одобрениот буџет (Excel/CSV образец од страницата) или внесете ставки рачно.
7. **Проекти** — внесете ги проектите (или увезете ги со CSV/XLSX образецот).

Јазикот на интерфејсот е **македонски**; секој корисник може да избере англиски во менито на профилот.

## 11. Известувања по е-пошта (Microsoft Graph)

1. Во Microsoft Entra ID (Azure AD) на Општина Битола регистрирајте апликација „е-Кабинет“.
2. **API permissions → Microsoft Graph → Application → `Mail.Send`**, потоа **Grant admin consent**.
3. Создајте **Client secret** и запишете ги `Tenant ID`, `Client ID` и тајната.
4. Ограничете ја апликацијата само на сандачето на испраќачот (Exchange Online PowerShell):

   ```powershell
   New-ApplicationAccessPolicy -AppId <Client ID> -PolicyScopeGroupId ekabinet@bitola.example -AccessRight RestrictAccess -Description "е-Кабинет: само сандачето за известувања"
   ```

5. Во конфигурацијата: `graph.enabled => true`, `tenant_id`, `client_id`, `client_secret`, `sender => 'ekabinet@bitola.example'`.
6. Тест:

   ```bash
   sudo -u www-data php /var/www/ekabineti-bitola/current/bin/graph-test.php vashe.ime@bitola.example
   ```

## 12. AI асистенти (OpenAI)

AI асистентите се **исклучени** додека не се конфигурираат. Сите барања се испраќаат од серверот; клучот никогаш не
стигнува до прелистувачот. Пред анализа се кријат ЕМБГ, е-пошти, телефони и IBAN; имињата на граѓаните и
странките не се испраќаат во брифинзите. Сите одговори на AI се на македонски (кирилица) и секогаш бараат човечка
потврда пред евидентирање.

Во PHP-FPM pool или во конфигурацијата:

```
OPENAI_ENABLED=true
OPENAI_API_KEY=<клуч на Општина Битола>
OPENAI_MODEL=gpt-5-mini
```

По промената: `sudo systemctl restart php8.1-fpm`. Користете посебен проект и клуч во OpenAI за Општина Битола,

## 13. Панел во Google Sheets (опционално)

1. Во Google Cloud создајте проект на Општината, вклучете **Google Sheets API** и создајте **сервисна сметка** со JSON клуч.
2. Создајте нова табела (Google Sheets) со листови со точно овие имиња:
   `Панел`, `Проекти`, `Услуги`, `Буџет`, `Прашања`, `Јавни набавки`, `Правни предмети`, `Услуги по сектори`.
   Листот `Панел` мора да има најмалку опсег `A1:M56`.
3. Споделете ја табелата со е-поштата на сервисната сметка како **Editor**.
4. Зачувајте го JSON клучот во `/var/www/ekabineti-bitola/shared/google-service-account-bitola.json`
   (сопственик `root:www-data`, дозволи `640`).
5. Конфигурација (PHP-FPM pool или `shared/e-kabineti.php`):

   ```
   GOOGLE_SHEETS_SYNC_ENABLED=true
   GOOGLE_SHEETS_SPREADSHEET_ID=<ID од URL на табелата>
   GOOGLE_SHEETS_DASHBOARD_GID=<gid на листот Панел>
   GOOGLE_APPLICATION_CREDENTIALS=/var/www/ekabineti-bitola/shared/google-service-account-bitola.json
   GOOGLE_SHEETS_SYNC_TIMEZONE=Europe/Skopje
   ```

6. Подготовка на образецот и проба:

   ```bash
   sudo -u www-data php /var/www/ekabineti-bitola/current/bin/sync-mayor-google-sheets.php --configure
   sudo -u www-data php /var/www/ekabineti-bitola/current/bin/sync-mayor-google-sheets.php --dry-run
   ```

7. Вклучете ја линијата за синхронизација во `/etc/cron.d/ekabineti-bitola`.

## 18. Проверки и решавање проблеми

| Проблем | Проверка / решение |
| --- | --- |
| Бела страница или 500 | `php81/storage/logs/` (JSON логови со correlation ID); логови на Apache; `php bin/diagnostics.php` |
| `The pdo_sqlsrv extension is required` | Чекор 3.2; `php -m` за CLI и `phpinfo()` за FPM |
| Грешка за TLS/сертификат кон SQL Server | `database.hostname_in_certificate` да одговара на сертификатот; само за тест `trust_server_certificate => true` |
| Прашалници (`???`) наместо кирилица | Колоните мора да бидат `NVARCHAR` (стандардно во шемата) и литералите `N'...'`; проверете ја колацијата (чекор 8.3) |
| Неправилно подредување на кирилица | Базата не е создадена со `Macedonian_FYROM_100_CI_AS`; создадете нова празна база со точната колација и повторете ги чекорите 8.1–8.2 |
| Не стигнуваат е-пораки | `php bin/graph-test.php …`; `graph.enabled`; Application Access Policy; логови `notifications.*` |
| AI е недостапен | `OPENAI_ENABLED`, `OPENAI_API_KEY`, излезен пристап до `api.openai.com` |
| Не се читаат `.xls` / `.doc` | `soffice --version`; корисникот `www-data` мора да може да го извршува LibreOffice |
| PDF не се анализира | `pdftotext -v` (пакет `poppler-utils`) |
| Распоредувачот не работи | `/etc/cron.d/ekabineti-bitola`, `php81/storage/logs/scheduler.log`, `php bin/scheduler.php` рачно |
